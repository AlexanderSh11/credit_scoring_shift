## Запуск скрипта

Обученные модели сохраняются в папку models/ в формате .pkl. Файлы не включены в репозиторий из-за большого размера. Для воспроизведения результатов достаточно запустить скрипт machine_learning.py

Для более быстрого запуска можно выбрать в этом файле лучшие гиперпараметры для каждой модели и вставить только их в params_grid в классе ModelTrainer (подбор гиперпараметров может занять продолжительное время)

Глобальные переменные для настройки находятся в функции main():

- TEST_SIZE = 0.2 - доля тестовой выборки (20%)
- TOP_N_FEATURES = 50 - количество отбираемых признаков Random Forest
- MIN_FREQUENCY_IN_CAT_FEATURE = 5 - минимальная частота категории для OneHotEncoder
- MODELS_DIR = PROJECT_DIR / "hw6" / "models" - папка для сохранения моделей

Данные загружаются из двух источников:

1. База данных - таблица application
2. CSV файлы с сгенерированными признаками - путь задается в main()

## 1. Подготовка данных

Объединены данные из таблицы application и сгенерированных признаков (application_features, bureau_features, bureau_balance_features)

Размер исходного датафрейма: 307511 строк, 193 признака

Целевая переменная: target (1 - дефолт, 0 - не дефолт). Доля дефолтов: 8% (сильный дисбаланс классов)

Удаление бесполезных признаков:

- ID клиента, другие ID (sk_id_curr, id_change_delay)
- Константные признаки

Заполнение пропусков:

- ext_source_1, ext_source_3 - медиана
- name_type_suite - мода (Unaccompanied)
- Категориальные признаки с большим числом пропусков (occupation_type, fondkapremont_mode, housetype_mode, wallsmaterial_mode, emergencystate_mode) - значение 'unknown'

## Выводы

Исходный датасет имеет сильный дисбаланс. Это основная сложность задачи. SMOTE не улучшил метрики

Несмотря на лучший ROC-AUC, градиентный бустинг показал recall = 0.03, то есть находит только 3% дефолтников. Градиентный бустинг последовательно исправляет ошибки предыдущих деревьев. Из-за дисбаланса модель предсказывает большинство как 0, даже с class_weight='balanced' деревья не могут эффективно обнаруживать редкий класс

Выбрана логистическая регрессия как лучшая модель. Логистическая регрессия находит 67% дефолтов (recall = 0.67). ROC-AUC = 0.7355, быстрое обучение (270 секунд), хорошая интерпретируемость модели

В кредитном скоринге recall важнее precision, потому что пропустить дефолт (False Negative) гораздо дороже для банка, чем ошибочно отказать хорошему клиенту (False Positive). Поэтому логистическая регрессия выбрана вместо градиентного бустинга, несмотря на более высокий ROC-AUC у GB
